# SafeRoute

SafeRoute — веб-навигатор с маршрутами по улично-дорожной сети и историческим контекстом преступлений и ДТП. Текущая география — Астана. Продукт помогает сравнивать варианты перед поездкой; оценка событий не является вероятностью происшествия и не гарантирует безопасность.

## Текущая стадия

Собран работающий веб-прототип навигатора: можно искать места, задавать начало и конец маршрута поиском, геолокацией или кликом по карте, выбирать транспорт, строить и сравнивать варианты, просматривать инструкции поворотов и начать сопровождение по маршруту. Данные происшествий хранятся в PostGIS, доступны карта, аналитика, импорт файлов и фоновая синхронизация разрешённых публичных слоёв Qamqor.

Это ещё не полноценная замена коммерческим навигаторам. Нет собственного мобильного приложения, офлайн-карт, аккаунтов, надёжного продакшн SLA, покрытия всей страны, live-трафика и подтверждённой модели прогнозирования. Сервисы маршрутизации, геокодирования и тайлов по умолчанию публичные; перед широкой эксплуатацией следует развернуть собственную или договорную инфраструктуру.

## Возможности приложения

- **Главная `/`** — назначение SafeRoute и переход к навигации.
- **Навигатор `/route`** — поиск адреса/места, выбор точек на карте, запрос геолокации браузера, выбор транспорта, построение альтернатив и пошаговые инструкции. Во время сопровождения приложение показывает прогресс и оставшееся расчётное время; при отклонении от линии маршрута предлагает построить маршрут заново. Озвучивание инструкций использует синтез речи браузера, если он поддерживается.
- **Карта `/map`** — слои преступлений и ДТП с периодами и категориями, пространственными агрегатами, кластеризацией/тепловым отображением и легендой.
- **Аналитика `/analytics`** — обзор, временные ряды, категории, горячие зоны и выгрузка CSV на основе доступных данных.
- **Администрирование** — страницы управления источниками и импортами доступны по `/admin/sources` и `/admin/imports`.

## Как работает навигация

### Маршрутизатор и транспорт

Маршруты запрашиваются у **Valhalla** по графу **OpenStreetMap**. Геокодирование выполняется через **Photon** (Komoot), смещённый к Астане. Карта показывает растровые тайлы OpenStreetMap через Leaflet. Геолокация и голосовые инструкции используют браузерные API при наличии поддержки и разрешения пользователя.

| Выбор в интерфейсе | Профиль Valhalla | Примечание |
| --- | --- | --- |
| Пешком | `pedestrian` | Пешеходная маршрутизация |
| Велосипед / самокат | `bicycle` | Для самоката отдельного профиля нет; используется велосипедный профиль |
| Автомобиль | `auto` | Маршрут по автомобильному графу |
| Мотоцикл | `motorcycle` | Маршрут по профилю Valhalla motorcycle |

Начальная и конечная точки привязываются к доступной сети Valhalla в радиусе до 100 м. Ответ включает геометрию маршрута, манёвры, расстояние и до двух альтернатив (если движок их вернул). Расстояние вычисляется по координатам геометрии маршрута. Время берётся из `trip.summary.time` Valhalla для выбранного профиля; клиент не заменяет его формулой «расстояние / условная скорость».

Показываемое время — оценка по дорожному графу и профилю. **Пробки, текущие перекрытия, задержки, погода и индивидуальная скорость не учитываются.** Для сопровождения оставшееся время складывается из длительностей оставшихся манёвров Valhalla. Поэтому фактическое время поездки может отличаться.

Если Valhalla недоступна либо не может привязать точки, приложение возвращает ошибку. Скрытого переключения на демонстрационный граф для маршрутизации нет.

### Оценка экспозиции событий

Модель `route-exposure-v3-qamqor` рассматривает реальные сегменты геометрии маршрута и записи в радиусе 150 м. Она раздельно считает историческую экспозицию преступлений и ДТП, нормируя взвешенные записи на километр. Вклад записи уменьшается с расстоянием и давностью (период полураспада 365 дней), учитывает доступное покрытие дат источника и качество координат. Неизвестным кодам категорий не назначается выдуманная тяжесть.

Для устойчивого вывода требуется минимум пять событий рядом с маршрутом и данные за выбранный период. Когда данных недостаточно, показывается соответствующее состояние, а маршрут всё равно строится. Если сравнение вариантов возможно, относительный индекс отражает порядок и величину различий только внутри этих вариантов. Он не абсолютен, не переносится на другие маршруты и не означает вероятность преступления/ДТП или уровень безопасности. Отсутствие записей не трактуется как низкий риск.

## Технологии

- **Frontend и серверные API:** Next.js 15, React 19, TypeScript.
- **Карта и визуализация:** Leaflet, OpenStreetMap raster tiles.
- **Маршруты:** Valhalla HTTP API, граф OpenStreetMap, costing-профили `pedestrian`, `bicycle`, `auto`, `motorcycle`.
- **Поиск мест:** Photon API с приоритетом Астаны.
- **Хранилище:** PostgreSQL 16 + PostGIS 3.4.
- **Проверка входных данных:** Zod; PostgreSQL-драйвер `pg`.
- **Инфраструктура:** Docker Compose; отдельный процесс фоновой синхронизации.

## Данные и источники

В `data/imports/` лежат стартовые GeoJSON-снимки публичных слоёв Qamqor по Астане:

- `qamqor_astana_crime_2026-01-01_2026-10-12.geojson` — преступления;
- `qamqor_astana_dtp_2026-01-01_2026-10-12.geojson` — ДТП.

Источник Qamqor GIS: [слой преступлений](https://gis.kgp.kz/arcgis/rest/services/KPSSU/crime/FeatureServer/1) и [слой ДТП](https://gis.kgp.kz/arcgis/rest/services/KPSSU/DTP/FeatureServer/0). Атрибуция в приложении: «Информация получена с официального интернет-портала qamqor.gov.kz».

Синхронизатор запрашивает только разрешённые публичные ArcGIS FeatureServer, выгружает необходимые поля для Астаны, применяет административную границу, постраничную загрузку, паузы, таймауты и повторы временных ошибок. Он сохраняет историю запусков. Синхронизация включена только для зарегистрированных подтверждённых источников; неизвестный адаптер не делает запросов. Интервал настраивается. При повторном импорте уникальные ключи источника и хэш записи предотвращают повторное добавление.

Сохраняются геометрия, дата, тип события, категория/исходные коды классификации, источник и атрибуция. Персональные поля, адреса и сведения о потерпевших или предполагаемых виновниках не предназначены для импорта. Публичные API карты возвращают агрегированное представление, а не точные координаты отдельных событий.

**Покрытие ограничено данными, реально доступными в источнике.** Статистическая полнота и точность точек на уровне метров не опубликованы. Фактическая дата последнего события может отставать от текущей даты. Диапазон первой и последней записи не доказывает полноту каждого дня. Перед интерпретацией результатов следует проверить даты и состояние источников в приложении.

## Хранение и структура БД

Миграции находятся в `migrations/` и применяются по порядку через `npm run db:migrate`.

- `data_sources` — метаданные, режим, покрытие, атрибуция и настройки синхронизации источников.
- `incidents` — типизированные события, категория и коды классификации, дата, точка `geometry(Point, 4326)`, источник, хэш и точность координат. Пространственные запросы ускоряются GiST-индексами; есть индексы по периоду, типу, категории и источнику.
- `import_jobs` — история файловых импортов, checksum, период данных, число принятых/отклонённых/дублирующихся строк и ошибки валидации.
- `source_sync_runs` — история синхронизаций и их результат.

Миграции также добавляют ограничения допустимых типов, индексы дедупликации и пространственные индексы. Данные базы переживают перезапуск контейнера в Docker volume `saferoute-postgres`.

## Быстрый запуск: Docker Compose

Нужны Docker Engine и Docker Compose Plugin.

```bash
cp .env.example .env
```

Замените пароль базы в `.env`, затем запустите:

```bash
docker compose up --build
```

Приложение откроется на <http://localhost:3000>. Compose поднимает PostGIS, применяет миграции и импортирует стартовые файлы при запуске приложения, затем запускает веб-приложение и worker синхронизации.

```bash
docker compose logs -f app sync-worker
docker compose down
```

`docker compose down -v` удаляет и volume базы вместе с импортированными данными. Используйте эту команду только если хотите сбросить локальную БД.

## Локальная разработка

Нужен Node.js 20.9+ и доступный PostgreSQL с PostGIS.

```bash
npm ci
cp .env.example .env
# В .env задайте DATABASE_URL для локального PostgreSQL/PostGIS
npm run db:migrate
npm run import:qamqor
npm run dev
```

Команды проекта:

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Запустить Next.js в режиме разработки |
| `npm run build` | Production-сборка |
| `npm run start` | Запустить production-сервер |
| `npm run lint` | ESLint |
| `npm run typecheck` | Проверка TypeScript без генерации файлов |
| `npm run db:migrate` | Применить неприменённые SQL-миграции |
| `npm run import:qamqor` | Импортировать файлы из `data/imports/` |
| `npm run sync:worker` | Запустить worker синхронизации |

## Конфигурация

Основные переменные из `.env.example`:

| Переменная | Назначение |
| --- | --- |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | База и учётные данные PostgreSQL |
| `DATABASE_URL` | Подключение приложения к PostgreSQL |
| `APP_PORT` | Порт приложения Docker Compose (по умолчанию `3000`) |
| `POSTGRES_PORT` | Порт PostgreSQL на хосте (по умолчанию `5432`) |
| `VALHALLA_BASE_URL` | Базовый URL Valhalla |
| `NEXT_PUBLIC_OSM_TILE_URL` | URL-шаблон тайлов Leaflet |
| `QAMQOR_SYNC_INTERVAL_MINUTES` | Период обновления источника (по умолчанию сутки) |
| `QAMQOR_SYNC_DELAY_MS` | Пауза между запросами к Qamqor |
| `SYNC_POLL_SECONDS` | Частота проверки worker на наступившие синхронизации |
| `DEV_ADMIN_MODE` | Локальный упрощённый доступ к операциям администратора; отключить вне локальной разработки |
| `ADMIN_API_KEY` | Ключ для защищённого доступа к административным API, если режим разработки выключен |

Не публикуйте `.env`, пароли и административные ключи. В публичном или рабочем окружении выставьте `DEV_ADMIN_MODE=0`, задайте защищённый `ADMIN_API_KEY` и замените публичные endpoint на сервисы с допустимыми условиями эксплуатации и достаточной ёмкостью.

## HTTP API

Основные публичные endpoints:

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/v1/health` | Состояние приложения и соединения с БД |
| `GET /api/v1/meta` | Метаданные системы и источников |
| `GET /api/v1/sources` | Доступные источники и их актуальность |
| `GET /api/v1/geocode?q=...` | Поиск мест через Photon |
| `POST /api/v1/routes/alternatives` | Маршруты Valhalla и оценка экспозиции вариантов |
| `GET /api/v1/incidents` | Записи с фильтрами по bbox, периоду, типу и категории |
| `GET /api/v1/map/aggregates` | Агрегаты происшествий для карты |
| `GET /api/v1/incidents/summary` | Сводка событий для выбранной области/периода |
| `GET /api/v1/analytics/overview` | Сводные показатели аналитики |
| `GET /api/v1/analytics/timeseries` | Временной ряд |
| `GET /api/v1/analytics/categories` | Категории |
| `GET /api/v1/analytics/hotspots` | Пространственные горячие зоны |
| `GET /api/v1/analytics/export.csv` | Выгрузка аналитических данных в CSV |

Административные endpoints для источников и импорта расположены под `/api/v1/admin/`. Импорт принимает CSV/GeoJSON с обязательным сопоставлением к зарегистрированному источнику и валидирует строки перед записью.

## Ограничения и дальнейшее развитие

- Сейчас поддерживается город Астана; национальная карта данных не подключена.
- ETA Valhalla не использует live-трафик и зависит от актуальности графа OpenStreetMap и конфигурации выбранного экземпляра Valhalla.
- Выбор «велосипед / самокат» использует единый профиль `bicycle`.
- Публичные Photon, Valhalla и OSM тайлы могут менять доступность и правила использования; у публичных демо-сервисов нет гарантированного SLA.
- Данные Qamqor не имеют опубликованных показателей статистической полноты и точности координат; записи могут быть неполными или уточняться источником.
- Индекс маршрута — относительное сравнение доступных вариантов и ограниченная историческая экспозиция, не прогноз и не оценка вероятности.
- Для полноценного потребительского продукта потребуются мобильные клиенты или интеграции с навигационными платформами, выбранный надёжный хостинг маршрутизатора/тайлов/геокодера, телеметрия качества, поддержка доступности и юридическая проверка условий данных.
- Предиктивная аналитика для правоохранительных органов не реализована. Для неё нужны законные основания и управление доступом к полным национальным данным, оценка качества/смещений, независимая валидация и человеческий контроль.
